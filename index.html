Keeping competitive exam practice in sync

YUDHA (Your Ultimate Digital Hiring Arena) is a Flutter learning arena for Indonesian civil-service (CPNS) and state-owned-enterprise (BUMN) applicants, combining aptitude-test practice, real-time quiz duels, progress tracking, and AI interview preparation. My contribution focused on the backend for real-time battles and study sessions.

Problem
Keep matchmaking, battle state, and study progress consistent across concurrent requests and player disconnects.
My role
Backend developer responsible for the NestJS and Socket.IO battle engine, matchmaking, match resolution, and study-session APIs.
Approach
Used Upstash Redis and Lua for first-in, first-out matchmaking, private room codes, and a 30-second reconnection window. Supabase PostgreSQL functions resolve matches and update rank points.
Key decision
Made match resolution idempotent so retries cannot apply the same result twice. Session locks and deterministic analytics keep study progress consistent.
Result
Delivered battle and study APIs, plus Firebase Cloud Messaging notifications for study streaks. The team placed 2nd at PIDI DIGDAYA x HACKATHON 2026.
Project scope
The Open Beta product includes a Learning Center, Standard, Focus, and Speed practice modes, progress tracking, and company- and role-specific AI interviews with text or voice answers. AI and voice availability depends on backend provider configuration.

Making document-grounded legal research easier to retrace

I built Lexara, a deployed research assistant that combines a fine-tuned Qwen 2.5 7B model with retrieval over more than 1,900 pages of Indonesian labor-law documents.

Problem
Retrieve relevant passages from a large legal-document collection, then make each answer easy to verify against its source.
My role
Built the model-training pipeline, hybrid retrieval system, and the responsive Lexara research interface.
Approach
Fine-tuned Qwen 2.5 7B with QLoRA and Group Relative Policy Optimization (GRPO), using custom rewards for structured reasoning.
Key decision
Combined keyword search (BM25) and vector search (ChromaDB) with Reciprocal Rank Fusion. HyDE query expansion and parent-child chunks add retrieval context.
Retrieval checks
Added FlashRank reranking, confidence thresholds, and a DuckDuckGo search fallback.
Result
Published the merged 16-bit model on Hugging Face Hub and deployed Lexara on Vercel with research prompts, document filtering, backend status, and traceable references.

Fish freshness: Multimodal classifier JUL–AUG 2025 Image and gas-sensor fusion for fish-freshness classification, with 84.3% macro F1. Multimodal transformersPyTorch · DINOv2 · Fusion Transformers View project ↗

Combining images and sensor readings to classify freshness

For our GEMASTIK XVIII research entry, I built a model that combines fish images with electronic-nose sensor readings and uses attention analysis to inspect its predictions.

FUSION-01

Grad-CAM evidence over vision tokens used to inspect the model’s spatial focus.

Problem
Combine visual and gas-sensor signals while preserving useful information from each modality.
My role
Designed the fusion architecture and contrastive-learning pipeline, handled class imbalance, and analyzed model attention.
Approach
Aligned DaFiF images and sensor streams by timestamp, filtered anomalies, and combined a DINOv2 vision transformer with an MLP sensor encoder.
Key decision
Aligned the modalities with a CLIP-style contrastive loss, then used bidirectional cross-attention to fuse them. Focal Tversky Loss addressed class imbalance.
Result
The project evaluation recorded 85.4% accuracy, 84.3% macro F1, and 92.7% peak F1 for the “Marginal” freshness class.
Model interpretation
Used Grad-CAM visualizations to inspect the image regions influencing predictions.

Recognizing handwritten Javanese script under time constraints

During the five-hour GEMASTIK XVIII final challenge, I built a classification pipeline for 20 handwritten Javanese script classes using Co-Scale Conv-Attentional Transformers (CoaT).

COAT-20

Confusion matrix showing predictions across 20 handwritten Javanese script categories.

XAI-02

Interpretation output used to inspect structural feature extraction after preprocessing.

Problem
Classify 20 handwritten script categories in a time-limited challenge with imbalanced training data.
My role
Handled image preprocessing, class weighting, transformer evaluation, and model interpretation.
Approach
Compared CoaT, Swin, and EfficientNet. Trained with frozen patch embeddings followed by progressive fine-tuning using AdamW and Kornia Focal Loss.
Key decision
Used macro F1 to evaluate performance across classes, and Captum Integrated Gradients to inspect stroke-level attribution and possible shortcut learning.
Result
Achieved a 96.7% test macro F1 across the 20 classes in the final competition evaluation.
